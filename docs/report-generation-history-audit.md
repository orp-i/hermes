# 历史报告审计与优化记录

> 审计对象：`/data/hermes.db` 中历史会话的报告 Markdown、PDF/DOCX 输出和 layout-review 文件。

## 发现的问题

历史报告主要集中在蛋白/重组表达分析场景，例如 TDP-43、PD-L1、MOTS-c。整体技术内容较充分，但更像技术分析记录，不够像 CRO 咨询客户交付物。

共性问题：

- 缺少明确的 `执行摘要`，客户需要先看到结论和推荐动作。
- `建议` 往往埋在技术章节中，例如“表达体系建议”“综合表达建议”，但缺少集中、优先级明确的建议区。
- 多数报告缺少 `下一步`，没有把结果转成可执行工作计划。
- 多数报告缺少 `风险与局限`，不利于客户判断证据强度和后续验证需求。
- 技术段落偏长，layout review 多次指出阅读疲劳。
- 表格样式和列宽历史上不稳定，证据/链接列容易拥挤。
- 长蛋白序列容易以单行长字符串出现，PDF 可读性差。
- 星级评分和 `$ / $$ / $$$` 成本符号在正式咨询报告里不够专业。
- 部分历史 layout review 提到链接列或图中文字可能出现乱码，需要质量检查提示。

## 已落地优化

- 新增 `cro-consulting-report` skill，把历史问题写成生成规范。
- 更新 `bio-analysis` skill，要求生信/蛋白报告转成 CRO 客户交付结构。
- 更新系统提示：报告生成从“固定两轮排版优化”改为“至少一轮，第二轮按质量警告/审阅反馈触发”，减少长报告进入 max-iteration 的风险。
- `render_report` 增加 CRO 交付质量警告：
  - 缺少执行摘要、建议、下一步、风险/局限。
  - 段落过密。
  - 长序列未换行。
  - 星级/符号化成本表达。
  - 乱码迹象。
  - 缺少客户含义或建议动作映射。
- PDF 渲染增强：
  - 表格单元格自动换行。
  - 大表可跨页并重复表头。
  - 长序列代码块自动按 80 字符换行。
  - 水平分隔线不再当普通段落渲染。
  - 增加页脚和页码。

## 后续可继续优化

- 为蛋白表达报告增加固定模板生成器，直接产出“决策摘要 / 表达策略矩阵 / 风险登记表 / 下一步工作计划”。
- 对历史报告中的 Markdown 自动迁移成新模板，用作对比样例。
- 将 layout-review 的自然语言反馈结构化为可机器检查的 checklist。

## 自动优化循环

已增加基于 layout review 的自动优化循环：

- 每次 `review_report_layout` 成功后，Hermes 会统计累计 review 次数。
- 默认每 10 次触发一次优化，可用 `HERMES_REPORT_SKILL_OPTIMIZE_EVERY` 调整。
- 优化器读取最近的 `*layout-review*.md`，抽取高频问题，如表格拥挤、段落密集、长序列、乱码链接、客户建议不清等。
- 生成的经验规则写入 `/opt/data/generated_skills/report-generation-feedback.md`。
- `skills_loader` 会同时加载人工 skills 和 `/opt/data/generated_skills`，该 feedback skill 设置为 `always: true`，之后所有报告生成都会自动吸收最近 review 反馈。
- 自动优化器不修改人工维护的 `skills/*.md`，便于审计、回滚和人工复核。
